# Датасет для ранжирования товаров

Одна строка в `impressions` — одна лента кандидатов для пользователя. В строке хранятся признаки кандидатов, эмбеддинг пользователя и история его событий. Целевые метки доступны только в `train` и `val`.

## Файлы

```text
competition/
  readme.md
  sample_submission.parquet
  train/
    impressions/
      part-*.parquet
      _SUCCESS
    item_embeddings/
      data.memmap
      data.meta
  val/
    impressions/
      part-*.parquet
      _SUCCESS
    item_embeddings/
      data.memmap
      data.meta
  test/
    impressions/
      part-*.parquet
      _SUCCESS
    item_embeddings/
      data.memmap
      data.meta
```

| Файл или папка | Содержимое |
| --- | --- |
| `impressions/part-*.parquet` | Ленты с признаками; в `train` и `val` также содержат метки. Файлы сжаты ZSTD; для чтения всей части датасета нужно использовать все её Parquet-файлы. |
| `impressions/_SUCCESS` | Пустой служебный маркер успешной записи. |
| `item_embeddings/data.memmap` | Таблица эмбеддингов товаров: непрерывный бинарный массив `int8` формы `(N, 128)` в порядке C. |
| `item_embeddings/data.meta` | JSON с типом `dtype`, формой `shape` и порядком `order` массива из `data.memmap`. |
| `sample_submission.parquet` | Шаблон предсказаний: одна строка на каждого кандидата из `test`. Файл сжат ZSTD. |

| Часть | Назначение | Лент | Parquet-файлов | Строк в таблице эмбеддингов |
| --- | --- | ---: | ---: | ---: |

## Даты и сбор

Даты зафиксированы; обе границы каждого периода включены.

| Часть | Начало | Конец |
| --- | --- | --- |
| `train` | 2026-09-06 | 2026-09-19 |
| `val` | 2026-09-22 | 2026-09-24 |
| `test` | 2026-09-26 | 2026-09-29 |

Период 2026-09-25 — 2026-09-25 оставлен зазором между val и test и не включён ни в одну часть датасета.

Train используется целиком для обучения, без выделения из него валидационной части. Val собирается отдельно от train, по тем же правилам, что test, чтобы воспроизводить его распределение.

В val и test используются только выдачи, в которых перед показом пользователю на проде все кандидаты были равномерно случайно перемешаны. Пользователи получали уже перемешанные выдачи; целевые метки сформированы из обратной связи после этих показов.

При подготовке файлов порядок кандидатов в val и test также перемешан одной общей перестановкой всех их полей. Соответствие между товарами, признаками, индексами эмбеддингов и таргетами сохраняется. Исходные позиции в val и test не публикуются.

Из всех частей датасета исключены товары, которые пользователь уже просматривал. В train для оставшихся товаров сохранены исходные позиции в `pos`, поэтому нумерация может содержать пропуски.

## Колонки

Обозначение `list<T>` означает массив значений типа `T`. Число кандидатов `M` и длина истории `H` могут различаться между строками. История содержит до 256 событий (`0 <= H <= 256`).

| Колонка | Тип | Размер в строке | Описание |
| --- | --- | --- | --- |
| `feed_id` | `int32` | Скаляр | Уникальный идентификатор ленты. Не пересекается между `train`, `val` и `test`. |
| `timestamp` | `int32` | Скаляр | Unix-время записи ленты в секундах. |
| `user_id` | `int32` | Скаляр | Обезличенный идентификатор пользователя. Нумерация общая для всех частей датасета. |
| `category_id` | `list<int8>` | `M` | Код категории каждого кандидата. Словарь общий с `history__category_id` во всех частях датасета. |
| `f1` | `list<float32>` | `M` | Нормализованный вещественный признак № 1. |
| `f2` | `list<float32>` | `M` | Нормализованный вещественный признак № 2. |
| `f3` | `list<float32>` | `M` | Нормализованный вещественный признак № 3. |
| `f4` | `list<float32>` | `M` | Нормализованный вещественный признак № 4. |
| `f5` | `list<float32>` | `M` | Нормализованный вещественный признак № 5. |
| `pos` | `list<int16>` | `M` | Исходная позиция кандидата, нумерация с 0. Есть только в `train`; после фильтрации позиции могут содержать пропуски. |
| `target` | `list<int8>` | `M` | Целевая метка кандидата: `1` — зафиксировано целевое действие, `0` — не зафиксировано. Есть только в `train` и `val`; это метка для обучения и оценки, а не входной признак модели. |
| `item_id__embedding_idx` | `list<int32>` | `M` | Индекс строки эмбеддинга кандидата в таблице `item_embeddings/data.memmap` этой части датасета. `-1` означает отсутствие эмбеддинга. |
| `item_id` | `list<int32>` | `M` | Обезличенный идентификатор товара. Нумерация общая для кандидатов и истории во всех частях датасета. |
| `user_embedding` | `list<int8>` | `128` | Эмбеддинг пользователя. |
| `history__item_id` | `list<int32>` | `H` | Обезличенные идентификаторы товаров из истории пользователя. |
| `history__category_id` | `list<int8>` | `H` | Коды категорий товаров из истории. Используется тот же словарь, что и в `category_id`. |
| `history__event_type` | `list<int8>` | `H` | Категориальный код типа события пользователя. |
| `history__event_source` | `list<int8>` | `H` | Категориальный код источника события пользователя. |
| `history__item_id__embedding_idx` | `list<int32>` | `H` | Индексы эмбеддингов товаров из истории в таблице `item_embeddings/data.memmap` этой части датасета. `-1` означает отсутствие эмбеддинга. |

## Согласованность массивов и кодов

- Все массивы длины `M` описывают одних и тех же кандидатов в одинаковом порядке. Например, `item_id[i]`, `f1[i]` и `target[i]` относятся к одному кандидату.
- В `val` и `test` кандидаты перемешаны одной общей перестановкой для всех их полей. Колонка `pos` отсутствует; исходный порядок кандидатов не сохраняется.
- Все массивы `history__*` имеют одинаковую длину `H`. Элементы с одинаковым индексом относятся к одному событию. История упорядочена от новых событий к старым и содержит последние события после фильтрации.
- `user_embedding` относится ко всей строке и не является массивом кандидатов или событий.
- Идентификаторы пользователей и товаров — целочисленные номера, а не исходные ID. Положительные значения обозначают известные объекты; `0` зарезервирован для отсутствующего ID.
- Вещественные признаки уже подготовлены для модели. Энкодеры обучены только на train и одинаково применены к val и test. Отдельные файлы энкодеров для чтения данных не нужны.
- Категории закодированы значениями `1..53`; `0` означает неизвестную или отсутствующую категорию. Не каждый код обязан встречаться в каждой части датасета.
- Типы событий закодированы значениями `1..10`, источники — `1..30`. Для неизвестного или отсутствующего значения используется `0`. Эти коды согласованы между частями датасета и не являются исходными номерами событий.

## Формат предсказаний

В `sample_submission.parquet` каждому кандидату из `test` соответствует отдельная строка. Ключи берутся из `feed_id` и элементов массива `item_id` тестовых лент.

| Колонка | Тип | Описание |
| --- | --- | --- |
| `feed_id` | `int32` | Идентификатор тестовой ленты. |
| `item_id` | `int32` | Идентификатор кандидата в этой ленте. |
| `score` | `float32` | Предсказанная релевантность: большее значение соответствует более высокой позиции. В шаблоне заполнено нулями. |

Замените `score` предсказаниями модели, сохранив ключи `feed_id` и `item_id` для всех кандидатов. Правильные ответы теста не входят в публичный архив.


## Эмбеддинги товаров

Индексы в `item_id__embedding_idx` и `history__item_id__embedding_idx` начинаются с 0 и выбирают строки из `item_embeddings/data.memmap` соответствующей части датасета. `-1` означает отсутствие эмбеддинга и не является индексом строки.

Для одного товара индексы в train, val и test могут различаться: каждая часть имеет собственную таблицу эмбеддингов. Идентификатор `item_id` при этом общий для всех частей и истории.
